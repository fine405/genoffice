# 项目交付状态一致性（预览版）

入口：**AI 校验右侧箭头 → 业务一致性（预览版）**，或选区 AI 弹层中的同名快捷项。AI 校验主按钮和 AI 分析仍使用原有对话流程。左侧“对话 / 校验”切换保留报告；收起侧栏不会停止正在进行的任务。

## 使用

1. 选中包含表头的范围，或在面板输入精确 A1 范围。仅光标不会自动扩大成整表。
2. 读取表头，确认项目标识、状态、最新进展和可选客户反馈列。猜测采用表头精确匹配，可手动修改。
3. 选择 Jev、DeepSeek Flash 或两个模型对比，读取检查范围，核对计数，再开始检查。
4. 查看问题、完整依据和模型分歧；定位后在表格中修改，点击“复查本行”。检查本身不修改单元格、样式或保存文件。
5. 通过“耗时、token 与费用”查看累计用量，并导出当前报告 JSON。

密钥和服务地址全部来自 **全局 Settings → AI 模型**。DeepSeek 使用该 provider 的全局配置，不受当前聊天 provider 选择影响。Jev 复用全局加密保存的密钥。面板只显示是否配置，不接收或显示密钥。语音设置与本功能无关。

## 判断与任务边界

- 固定规则 `delivery-acceptance-v1`：只有客户明确验收通过当前项目本次交付，才支持状态“已完成”。
- 一致、不一致、依据不足为三种业务判断；失败、停止、数据变化独立展示。失败不会伪装为“依据不足”。
- 状态值去除首尾空白后，只有“已完成”调用模型。“未开始 / 进行中 / 待验收 / 已暂停 / 已取消”不适用；其他状态待补充。完全空行跳过。
- 首版最多 1,000 条记录、64 列；字段最多 4,000 字，过长拒绝，不静默截断。包含范围内隐藏与筛选隐藏的行。
- 每 100 行加载必要列，复用懒加载接口和当前未保存内容。读取失败或期间数据变化会要求重读，不能当作空表。
- 每行形成固定输入快照；报告绑定工作簿、工作表、范围、映射、规则版本和具体模型。修改相关列后失效；排序、移动、插删行列、工作表替换后禁用旧定位。表头变化也要求重读。
- 单行复查只调用该行选定的模型。关闭工作簿取消请求。正在运行时禁止启动通用 AI 修改或重复校验。
- 报告仅在会话内保留，可手动导出。模型输入不包含人工标签，不跨行合并实体，也不自动修正状态。

## 模型对比口径

- 固定 Jev `jev-1.13.0` 与 DeepSeek `deepseek-flash`；响应的实际版本保存在结果中。
- 同一条记录、同一规则、同一三分类定义。每个模型并发 1，两个模型对比时同时发出；当前行两边都结束后处理下一行。没有自动重试，超时 30 秒，DeepSeek 关闭思考。
- 逐行请求便于对齐对比与局部复查；未实现 Jev 多行合批吞吐优化，不宣称这代表其最高吞吐。
- 展示逐行原始结果、模型分歧、累计请求耗时、最近整批/复查耗时、实际 input/output token 和已知费用。复查、失败、取消的返回用量保留在累计值中。取消后服务端仍可能计费；缺失用量不会被当作确定零成本。
- 官方价格基准日期 2026-09-21，沿用 Slides 的共享计费函数。DeepSeek 展示峰谷费率区间；自定义网关或缺少缓存用量时费用未知。
- Jev confidence < 0.8 提示待复核，阈值尚未校准，不能当作准确率。DeepSeek 不生成伪置信度。普通表格无标签，因此界面不显示准确率。

## 演示与离线评估

示例工作簿位于 `outputs/01a0bf91-0f09-71c0-8a39-2eb9b5aac1a2/项目交付台账-业务一致性演示.xlsx`。24 条虚构项目记录：演示台账 18 条、独立测试 6 条。标签单独保存在同目录 `business-check-labels.json`，演示步骤在 `演示说明.md`。

使用完整范围导出报告后，可离线核对标签；此命令不调用 API：

```bash
npx tsx apps/sheets/scripts/evaluate-business-check.ts /path/to/business-check-report.json outputs/01a0bf91-0f09-71c0-8a39-2eb9b5aac1a2/business-check-labels.json
```

只匹配同名工作表、内容完全一致且未失效的输入。按 development/test 分开输出混淆矩阵、有效输出覆盖率、有效输出上的准确率、不一致召回率、正常行误报率，以及缺失/变化/失败数量。先用演示集调提示或阈值，再保留独立测试集作最终检查；这只是小规模合成样例，不代表生产准确率，不报告 p95。
